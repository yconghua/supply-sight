# 链眼 · 供应链数据分析与预警系统 · 使用手册

> **链眼**（Supply Sight）是一套面向中小制造企业采购主管的**供应链数据分析与预警系统**。
> 用四个模块回答三个真实的业务问题：**库存压了多少钱 / 哪家供应商不靠谱 / 采购成本为什么降不下来**。
> 一个**开箱即用的本地桌面应用**（Electron + Vue 3 + MySQL）：不需要自己搭后端服务，
> Electron 主进程直连你的 MySQL，登录即用，数据全部留在本机、不上传云端。

## 这是什么

链眼是一个本地运行的桌面应用，**下载源码 → 装依赖 → 启动 → 填一次数据库连接 → 登录使用**。数据全部落在你自己的 MySQL 里，没有云端、没有第三方服务。

**它要解决的三个业务问题：**

| 业务问题 | 对应模块 | 看什么指标 |
| --- | --- | --- |
| 库存压了多少钱 | 库存健康度 | 期末库存金额、周转天数、呆滞占用金额、ABC 分类 |
| 哪家供应商不靠谱 | 供应商绩效 | 准时交付率（OTD）、来料不良率（PPM）、平均延迟、综合评分 |
| 采购成本为什么降不下来 | 采购成本 | 加权均价、价格指数、涨幅榜、月度价格走势 |

三个模块各自的异常，最终在 **预警中心** 统一收口成可处理的预警；而支撑这些分析的原始数据，来自随应用一起提供的 **数据模拟器**。

> **关于数据来源**：真实企业采购数据难以获取，本项目内置数据模拟器，用统计算法生成一套**具备真实统计特征、且三张表逐月勾稽相符**的采购数据。它不是随手编的数字，而是一个固定种子的推演引擎跑出来的结果（详见[数据是可信的吗](#数据是可信的吗)）。换上企业真实数据后，所有指标与预警算法同样适用。

## 快速开始：两条命令跑起来

在项目根目录（含 `package.json` 的目录）打开终端：

```bash
# 第 1 步：安装依赖（首次需要，约 1~3 分钟）
npm install

# 第 2 步：启动开发模式（自动打开应用窗口）
npm run dev
```

启动后会出现 Electron 窗口并停在**登录页**——**此时还没有任何数据库连接，需要先完成下面的「添加数据库」才能登录。**

## 第一步：添加数据库（自动建库建表）

**系统不内置任何默认连接**，首次使用必须自己添加一个。整个过程不需要手写 SQL：

1. 在登录页点击「基础配置 → 添加数据库」；
2. 填写你的 MySQL 连接信息（主机 / 端口 / 用户名 / 密码 / 数据库名）；
3. 点击确认，主进程会自动完成：
   - **建库**：`CREATE DATABASE IF NOT EXISTS`（不存在才创建，字符集 utf8mb4）；
   - **建表**：按文件名顺序执行 `electron/db/schemas/` 下的全部 `.sql`；
   - **写入种子数据**：默认管理员（账号 `admin` / 密码 `admin123`）+ 6 条默认预警规则；
4. **添加的第一个连接会自动生效**，返回登录页用默认账号登录即可。

建库完成后，库里会有 10 张表：

| 表 | 存什么 |
| --- | --- |
| `user` | 账号 |
| `supplier` | 供应商主数据（含交付延迟均值/标准差、不良率） |
| `material` | 物料主数据（含订货点、最小起订量、采购提前期、ABC 分类） |
| `purchase_order` | 采购订单主表（承诺交期 + 实际到货日，OTD 判定依据） |
| `purchase_order_item` | 订单明细（到货数、合格数、不良数分开存，PPM 直接可算） |
| `inventory_flow` | 出入库流水（库存数量变动的唯一事实来源） |
| `inventory_snapshot` | 月度库存快照（期初 + 入 − 出 = 期末） |
| `alert_rule` | 预警规则（JSON 参数配置，内置 6 条） |
| `alert_record` | 预警命中记录 |
| `sim_run` | 数据生成记录（随机种子 / 埋点配置 / 勾稽自检结果） |

**几个关键约定：**

- 数据库的连接信息保存在应用所在电脑的**用户数据目录**（`db-connections.json`），**不会进入代码仓库**，换机器需重新添加；
- 添加第二个连接后，可在「基础配置」里随时切换，多套连接运行时切换、无需重启；
- 注意：**新表不会在普通重启时自动建**。给「已存在」的数据库加表 / 加列，只有两种触发时机：① 再添加一个新的数据库连接；② 升级 `package.json` 的 `version` 后重启一次。升级迁移会**重跑全部 `.sql`**（新表用 `CREATE TABLE IF NOT EXISTS` 创建），并自动比对每个 `.sql` 声明的列与库中实际列，**缺失的列自动 `ALTER TABLE ... ADD COLUMN` 补齐**；全部库都成功后才写入新版本号，中途失败则下次启动自动重试（已完成的操作幂等跳过，不会重复执行）。

## 第二步：生成一套数据（否则页面是空的）

**系统不预置任何示例数据。** 首次登录后，首页与四个业务模块会提示「暂无数据」，此时需要先造一套数据。

进入左侧导航 **数据模拟器 → 模拟生成**，保持默认参数点「开始生成」即可：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| 随机种子 | 20260911 | **同一种子两次生成结果完全一致**，便于复现与演示 |
| 物料数 | 60 | 支持 1 ~ 300 |
| 供应商数 | 12 | 支持 1 ~ 60 |
| 模拟月数 | 24 | 支持 1 ~ 60，24 个月能支撑同比 / 环比分析 |

生成过程在后台异步推进，页面实时显示进度；单次生成默认规模约 **4.6 万条**数据（订单约 930 张、出入库流水约 4.2 万条、月度快照 1440 条），推演本身耗时不到 1 秒。

生成完成后，页面上会显示：

- **勾稽自检结果**（5 项，全部打勾才算通过）；
- **本次埋点说明**：这一套数据里故意制造了哪些异常（哪几家供应商不靠谱、哪些物料会呆滞、哪些物料在涨价）；
- **数据指纹**：用同一种子再生成一次，指纹应当完全一致；
- **生成历史**：历次生成记录（运行编号 / 种子 / 规模 / 条数 / 自检是否通过）。

生成完成后，回到首页就能看到三个业务问题的答案，四个模块也都有数据了。

> 每次生成会**清空业务表后重建**，但保留预警规则（规则是配置）与生成历史（用于指纹比对）。

## 功能模块

左侧导航结构如下（导航由 `src/config/navConfig.js` 单一数据源驱动）：

### 供应商绩效

- **绩效总览**：按准时交付率升序排名，最差的排在最上面；可勾选「只看需关注」，一眼锁定该约谈的供应商。
- **交付与质量明细**：逐单核对承诺交期与实际到货日、每批来料的合格数与不良数——OTD 与 PPM 就是从这张表汇总出来的；支持按供应商 / 状态 / 是否延迟筛选。

### 库存健康度

- **库存总览**：期末库存金额、呆滞金额与占比、平均周转天数、低于订货点的物料数；按 ABC 分类展示资金分布；物料级明细带资金占比条与状态标记（呆滞 / 低于订货点 / 正常）。
- **呆滞与周转**：把呆滞物料单独列出来，显示周转天数、最后出库日期、无出库天数与占用金额——直接回答「钱压在了哪些物料上」。

### 采购成本

- **成本总览**：累计采购金额、平均价格指数、涨幅超 5% 的物料数；按物料列出加权均价、基期价与本期价、涨幅。
- **价格趋势**：展示关键物料的月度加权均价走势，把「连续上涨」这件事用曲线讲清楚。

### 预警中心

- **预警列表**：点「立即扫描」按规则全量求值，把越过阈值的对象挑出来，显示实测值、阈值与一句业务白话解释；可按模块 / 严重度 / 状态筛选，并标记处理或忽略。
- **预警规则**：只读展示库里的规则配置（6 条默认规则 + 三类求值方式说明）。

### 数据模拟器

- **模拟生成**：配置规模与随机种子 → 一键生成 → 查看进度、勾稽自检、本次埋点说明与生成历史。

### 首页

把三个业务问题的答案摊在最前面（库存金额 / 最差供应商 / 价格指数），带未处理预警提示、关键指标一览和本次数据来源（种子 / 规模 / 条数 / 自检结果），并给出四个模块的入口。

## 数据是可信的吗

数据模拟器不是「每张表各造各的随机数」，而是**一个推演引擎逐日推进，一套数据三张表自洽**：

```
统计输入                    逐日推演（730 天）                     产出
┌────────────────┐         ┌──────────────────────────┐         ┌─────────────────┐
│ 供应商交付参数  │         │ 日需求 = 基值             │         │ purchase_order  │
│  正态分布 μ/σ  │────────▶│   ×(1+正弦季节项)         │────────▶│  采购订单       │
│ 物料需求参数    │         │   ×(1+正态噪声)           │         │ inventory_flow  │
│  正弦季节性     │         │  → 出库消耗库存            │         │  出入库流水     │
│ 价格游走参数    │         │  → 库存跌破订货点则下单     │         │ inventory_      │
│  随机游走+漂移  │         │  → 订单到货 = 承诺期       │         │  snapshot       │
└────────────────┘         │     + max(0, round(N(μ,σ)))│         │  月度库存快照   │
                           │  → 到货入库（扣不良品）      │         └─────────────────┘
                           └──────────────────────────┘
```

关键之处在于**因果关系是正的**：采购订单是「因为库存跌破订货点」才产生的，入库流水是「因为订单到货」才产生的，月度快照是「由流水汇总」出来的。所以三张表天然勾稽得上，用 SQL 一验就平。

**勾稽自检 5 项**（模拟器页面上显式展示，任意一项不平就红字报警）：

| # | 自检项 | 含义 |
| --- | --- | --- |
| 1 | 期初 + 入 − 出 = 期末 | 每个物料逐月核对，快照与流水必须对得上 |
| 2 | 期末库存不为负 | 出库不得超过现有库存 |
| 3 | 库存金额 = 期末量 × 期末单价 | 金额与数量、单价三者一致 |
| 4 | 订单合格数量 = 入库数量 | 不良品不入库，因此入库量对应合格数 |
| 5 | 同种子两次生成结果一致 | 固定种子 PRNG，数据指纹可逐字节比对 |

**可复现**：随机数用自写的 `mulberry32` 固定种子算法，同一种子两次生成的结果完全一致（数据指纹可直接比对），演示时可以重放。

**统计特征是真在的**：供应商的准时率由**延迟均值和标准差的比值**决定（而非只调均值）；需求带正弦季节项（模拟旺季淡季）；采购单价按随机游走波动，部分物料带正漂移。这些特征让 OTD、周转天数、价格指数这类指标算出来是有业务意义的，而不是一堆噪声。

**主动埋点**（造出来的坑，预警规则必须能命中，形成闭环）：

- 指定 2 家供应商延迟均值大、波动也大、不良率偏高 → 必然成为「不靠谱的那两家」；
- 指定 4 个备件在推演中「产品停产、停止领用」，配合偏大的最小起订量 → 必然形成呆滞库存；
- 指定 2 个物料的价格随机游走带正漂移 → 必然触发「连续上涨」的趋势型规则。

## 指标口径说明

| 指标 | 计算口径 | 说明 |
| --- | --- | --- |
| **OTD**（准时交付率） | 准时到货订单数 ÷ 已到货订单数 | 在途未到货的订单**不计入分母**，否则会虚低 |
| **PPM**（来料不良率） | 不良数量 ÷ 到货数量 × 1,000,000 | 不良品不入库，入库量对应合格数 |
| **综合评分** | 准时率 × 60% + 质量得分 × 40% | 质量得分按 PPM 线性折算，10000 PPM（即 1% 不良）得 0 分 |
| **周转率 / 周转天数** | 周转率 = 期间出库金额 ÷ 平均库存金额；周转天数 = 期间天数 ÷ 周转率 | 金额口径，避免「按数量算」在单价差异大时失真 |
| **ABC 分类** | 按年消耗金额帕累托 80 / 15 / 5 | A 类物料少但占用资金最多，是管控重点 |
| **加权均价** | 采购金额 ÷ 采购数量 | **不对单价直接取平均**——同物料各批次数量差异大，直接平均会被小批量试单带偏 |
| **价格指数** | 本期加权均价 ÷ 基期加权均价 | 基期取序列第一个月，本期取最后一个月，首末对比反映累计涨幅 |
| **呆滞判定** | 周转天数 > 180 天 **且** 近 60 天无出库 | 两个条件缺一不可，避免把「正常慢销但仍在领用」的物料误杀 |

> 指标缺失时页面显示「—」而不是 0。例如某供应商还没有到货记录，OTD 根本算不出来，显示 0% 属于误导；规则引擎遇到缺失值同样跳过该条——**「无法判定」和「判定为不合格」是两回事**。

## 预警规则

规则以 JSON 存在数据库里（`alert_rule` 表），引擎按类型分派求值器。**新增一条规则只需要加一行配置，不用改代码。**

**三类规则：**

| 类型 | 求值方式 | 参数结构 |
| --- | --- | --- |
| `threshold` 阈值型 | 直接比大小 | `{metric, op: >,<,>=,<=, value, window_months?}` |
| `trend` 趋势型 | 连续 N 期同向变化，且累计变化超阈值 | `{metric, direction: up,down, periods, min_change_pct?}` |
| `composite` 组合型 | 用「且 / 或」组合多个阈值条件 | `{logic: and,or, conditions: [...]}` |

**内置 6 条默认规则：**

| 规则编码 | 名称 | 模块 | 类型 | 触发条件 | 严重度 |
| --- | --- | --- | --- | --- | --- |
| `SUP_OTD_LOW` | 供应商准时交付率过低 | 供应商 | 阈值型 | 近 3 个月 OTD < 90% | 高 |
| `SUP_PPM_HIGH` | 供应商来料不良率偏高 | 供应商 | 阈值型 | 近 3 个月 PPM > 5000 | 高 |
| `INV_TURNOVER_SLOW` | 库存周转天数超标 | 库存 | 阈值型 | 周转天数 > 180 天 | 中 |
| `INV_DEAD_STOCK` | 呆滞库存预警 | 库存 | **组合型** | 周转天数 > 180 天 **且** 近 60 天无出库 | 高 |
| `COST_PRICE_RISING` | 采购单价持续上涨 | 成本 | **趋势型** | 连续 3 个月上涨且累计涨幅 > 5% | 中 |
| `COST_INDEX_HIGH` | 采购价格指数偏高 | 成本 | 阈值型 | 价格指数 > 1.1 | 中 |

> 「呆滞库存」是组合型规则的典型用例：只看周转慢会把正常慢销品误杀，必须加上「近 60 天无出库」才站得住。

**关于重复扫描**：预警记录以「规则 + 对象 + 账期」为唯一键去重，反复扫描同一账期只更新实测值、不会新增行，所以预警列表不会越扫越多。

## 打包成 exe / 安装包

```bash
npm run pack
```

该命令 = `npm run build`（Vite 构建前端到 `dist/`）+ `electron-builder`（打包安装包）。

**输出目录**：`release/`（已被 `.gitignore` 忽略，不会提交到仓库）。Windows 下产出 NSIS 安装包（`.exe`）。

**注意事项：**

1. **建议用管理员终端执行**（右键终端 → "以管理员身份运行"）。electron-builder 在 Windows 上创建安装程序时需要写系统目录 / 符号链接的权限，普通终端偶发 `EPERM` / 权限错误；
2. 首次打包会下载 electron 二进制与 NSIS 工具，**耗时较长**，请耐心等待；国内网络慢可先配置镜像（见 [FAQ](#常见问题-faq)）；
3. 若被杀毒软件拦截生成的 exe，属于误报，添加信任或白名单即可；
4. 产物在 `release/` 下，把 `*.exe` 分发给别人即可，对方无需安装 Node（但**运行仍需一个 MySQL 实例**，首次打开在应用里添加连接）。

**推送 main 分支自动发布（GitHub Actions）：**

仓库已内置 `.github/workflows/release.yml`：推送 `main` 分支到 GitHub 后，CI 会读取 `package.json` 的版本号——若该版本对应的 tag 尚不存在，则自动打 tag 并打包发布；版本号未变化则自动跳过。CI 在 Windows 环境执行 `npm ci` → `npm run build` → `electron-builder`，并把安装包上传为 **GitHub Release**。

**发版步骤：** 改 `package.json` 里的 `version` → 提交并推送：

```bash
git add package.json
git commit -m "chore: release v0.0.3"
git push origin main
```

tag 和 Release 全部自动完成，无需手动打 tag。也可以在 GitHub Actions 页面手动触发（`workflow_dispatch`，同样会检查 tag 是否已存在）。CI 使用 `npm ci`，请确保 `package-lock.json` 已提交。

**应用内检查更新：** 「系统管理 → 关于 → 版本号」可手动检查更新：应用请求更新源仓库的 GitHub Releases 最新版本，与本地版本（`package.json`）做语义化对比，发现新版本时展示更新说明并引导前往下载页。

> **前提：更新源仓库必须设为公开**（检查更新走 GitHub 匿名只读 API，私有仓库会返回 404），且已通过上面的流程发布过 Release。检查更新的仓库地址在 `electron/ipc/sys.js` 顶部的 `UPDATE_REPO` 常量里配置，改成你自己的 `owner/repo` 即可。

## 二次开发：加自己的业务模块

一个业务模块涉及以下环节，数据流向：**页面 → `src/api` → `preload` → IPC → Service → Repository → MySQL**：

| # | 文件 | 作用 |
| --- | --- | --- |
| 1 | `electron/db/schemas/NN_表名.sql` | 建表 + 种子数据（升级版本号后自动执行） |
| 2 | `electron/db/repositories/xxxRepository.js` | 数据访问层（SQL 只写在这里，参考 `userRepository.js` / `BaseRepository.js`） |
| 3 | `electron/services/xxxService.js` | 业务服务层（指标计算放在这里，参考 `metricService.js`） |
| 4 | `electron/ipc/xxx.js` | IPC 通道（在 `electron/ipc/index.js` 注册） |
| 5 | `electron/preload.js` | 用 `createInvoke` 把通道暴露到 `window.api` |
| 6 | `src/api/index.js` | 前端 API 封装（调用 `window.api.xxx`） |
| 7 | `src/pages/xxx/` | 页面组件（分组落地页为 `index.vue`） |
| 8 | `src/config/navConfig.js` | 左侧导航注册（单一数据源，路由自动生成） |

**分层约定（务必遵守）：**

- 渲染层**不直接访问数据库**，也不写 SQL；
- SQL **只出现在 Repository 层**；
- 重计算（数据生成、指标聚合）放在**主进程**，且必须异步 + 分批，避免卡住 IPC 响应；
- 页面不造数——所有展示值来自主进程返回，某字段缺失时显示「—」而不是 0。

技术栈：Vue 3（`<script setup>`）+ Vue Router 4 + Vite 5 + Electron 31 + MySQL（mysql2）+ bcryptjs（密码哈希）。图表为轻量自绘（CSS / SVG），不依赖第三方图表库，安装即用。

## 常见问题 FAQ

**Q1：`npm install` 很慢 / 卡住？**
国内网络建议使用 npmmirror 镜像。在用户目录（`~/.npmrc`）写入：
```bash
registry=https://registry.npmmirror.com
electron_mirror=https://cdn.npmmirror.com/binaries/electron/
electron_builder_binaries_mirror=https://cdn.npmmirror.com/binaries/electron-builder-binaries/
```

**Q2：登录后页面都是空的 / 提示「暂无数据」？**
这是正常的——**系统不预置示例数据**。请先到「数据模拟器 → 模拟生成」点一次「开始生成」，约几秒后四个模块就有数据了。

**Q3：启动后白屏？**
开发模式请确认 5173 端口未被占用（`npm run dev` 输出里 Vite 正常起来）；打包版使用 hash 路由，一般不会白屏。可先清缓存（个人中心 → 系统管理 → 清理缓存 → 全部）再试。

**Q4：改了主进程代码没生效？**
`electron/` 下的代码不会热更新，改完需要**重启应用**（`Ctrl + C` 停掉再 `npm run dev`）。

**Q5：添加数据库提示连接失败？**
- 确认 MySQL 服务已启动、端口正确；
- 确认账号密码正确且**有建库权限**（程序要执行 `CREATE DATABASE`）；
- 远程 MySQL 需确认账号允许从当前 IP 访问（`%` 或指定主机授权）。

**Q6：`npm run pack` 报权限错误？**
改用**管理员终端**重试（见「打包成 exe」注意事项第 1 条）。

**Q7：打包下载 electron 二进制超时？**
同样配置上面的镜像后重试；或把 `node_modules` 删掉重新 `npm install` 一次。

**Q8：默认管理员密码忘了？**
连接数据库后直接改 `user` 表里 `admin` 行的 `password` 字段（值需为 bcrypt 哈希），或重开一个数据库连接重新初始化。
